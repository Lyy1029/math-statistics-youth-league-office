# 任务分派、审核与报送

## 用户于 2026-08-13 确认的当前角色链

通常按以下链路办理：

`团委书记（老师）发起/起草 → 团委副书记（学生）安排 → 办公室部长/副部长研判并承办或派给干事 → 执行人提交成果 → 逐级向上审核`

- 团委书记：确定任务要求；审核需要报送学校的文件；审核后由其发送至学校相关部门。
- 团委副书记：接收书记任务，明确承办部门、目标和时限。
- 办公室部长/副部长：判断紧急程度、风险与工作量；可自行承办，也可分派给干事；负责初审、协调和向上报送。
- 干事：按任务书执行，自检后先交部长/副部长，不直接把未审核成果报给老师或校级部门。

这是用户确认的当前通常链路。若任务来自学校通知、其他部门或临时现场指令，先记录真实来源，再由当前负责人确认是否沿用此链。用户另明确：需报送学校的文件由团委书记审核后发送；在用户更新该口径前把它作为当前硬闸门。

## 接单时必须形成的任务卡

常规批量制证例外：输入齐全时，按 [活动证明与突出贡献证明](certificate-workflow.md) 使用简化制证批次记录，无需另建完整任务卡。存在资格争议、名单冲突、补开/修订或新制度要求时，再恢复完整记录。

至少记录：

- 任务名称、来源和原始通知；
- 目标产物与正式模板；
- 学年、学期、活动正式全称；
- 对象范围、材料字段和证据来源；
- 截止时间、建议内部截止和紧急程度；
- 承办人、初审人、上级审核人、最终发送人；
- 报送渠道、是否需签字/盖章/公示；
- 个人信息等级和允许访问范围；
- 当前状态、异常和待确认项。

部长/副部长根据紧急程度决定“自己处理”或“派给干事”，但不得省略必要自检和有权人审核。常规批量制证按上述简化链路办理，不在每个层级重复同一套检查。其他紧急任务若经负责人明确要求压缩步骤，应记录指令、被压缩步骤和事后补录情况。

## 输出前的四道闸门

1. **来源闸门**：使用原始通知和最新正式模板，不能凭往年文件替代现行规则。
2. **内容闸门**：核对对象、日期、学年、活动全称、角色、份数、格式及附件。
3. **权限闸门**：仅向任务链中的授权角色展示原始名单和敏感材料。
4. **发送闸门**：成果逐级提交；需要报学校的文件只有经团委书记审核后方可发送。

## 常见任务的责任边界

| 任务 | 执行产物 | 必须保留的人为决定 |
| --- | --- | --- |
| 通知 | 通知草稿、报名入口、截止提醒 | 受众、激励政策、发布时间、发布人 |
| 活动 | 倒排期、分工、签到、会务清单、复盘 | 活动批准、岗位负责人、应急指挥 |
| 证明 | 待审核 Word/PDF、人数与异常清单 | 资格确认、最终名单、盖章批准 |
| 评奖评优 | 条件清单、收件台账、核验报告、报送包 | 名额、资格解释、最终审核、公示 |
| 招新留任 | 表单、去重检查、评分汇总、调剂清单 | 评分规则、回避、录取与调剂决定 |
| 信息台账 | 年度收集计划、字段检查、全院人数核对、变更记录 | 收集依据、字段、访问授权、保存和删除期限 |

不得替老师、负责人或评审人员作出资格、录取、处分、加分、表彰、公示等实质决定。
