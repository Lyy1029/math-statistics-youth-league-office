# 学生通知改写与发布准备

本规范适用于把学校通知、团委书记转发消息、附件或公众号文章改成可发给学生、班群或年级群的通知。2026-08-14 提供的三组对照样例只用于学习格式和受众转换，不是事实模板；不得沿用其中的活动、日期、邮箱、金额或资格条件。

## 先建立事实底稿

逐项记录以下字段及来源：

| 字段 | 核验重点 |
| --- | --- |
| 任务 | 正式名称、主办方、学生要做什么 |
| 对象 | 年级、学历、专业、身份或人数限制 |
| 时间 | 活动时间、学院内部截止、官方截止分别记录 |
| 地点/方式 | 线下地点、线上平台或集合安排 |
| 条件 | 资格、时长、数量门槛及统计口径 |
| 权益 | 证明、证书、时长、补贴、保险或评优的限制条件 |
| 报名 | 表单/材料、命名、提交顺序和正式渠道 |
| 配套材料 | 附件、公众号文章、链接、二维码是否真的随消息发送 |
| 后续 | 是否需建群、补材料、培训、集合或持续协调 |

来源只标为 `消息正文 / 已提供附件 / 已查看文章或链接 / 学院本次决定`。任何数字、日期、资格、权益、命名和渠道若没有来源，列入待核验，不得进入可发送成稿。

“交通住宿有保障”“符合条件可获证明”等概括性权益若缺少范围、标准或条件，只能按来源记录为待核事实，不能浓缩成无条件承诺。

## 从学院视角改成学生视角

1. 删除“各位书记”“请各学院动员”“有意向的学院反馈”等内部传达语。
2. 用一句导语说明正式活动名、面向对象和核心行动；必要时保留主办方以便识别来源。
3. 按学生决策顺序重排：`做什么 → 谁能报 → 何时何地 → 能获得什么 → 怎样报名 → 何时截止 → 后续如何通知`。
4. 把“学院联系上级”拆成学生可执行的步骤；存在学院预审时明确写成“先向学院报名/确认，再按要求提交”。
5. 保留原文的限制语气，如 `拟、可、原则上、左右、最高、有效、经审核、符合条件者`，不要把可能权益写成保证。
6. 相对时间仅在原消息时间戳可靠时换算；否则写入待核验。学院为收口设置的时间明确标为“学院内部截止”，不要冒充官方截止。

## 微信与年级群格式

- 第一行使用 `【通知】`，复杂或较长活动可在下一行单列正式名称。
- 正文保持正式、直接、适合手机阅读；一段只承担一个功能，条件较多时编号列出。
- 简单事项通常控制在约 250–350 字；复杂招募可到约 400–600 字，但不得为压缩而删除资格、上限、材料或截止。
- Emoji 只作导航，每段最多一个并保持语义稳定；平台表情不是必需项。
- 建议标签：`⭕️活动时间`、`📍活动地点`、`🔘活动内容`、`ℹ️报名条件`、`✅保障/激励`、`❗️报名方式`、`⏰截止时间`、`💬后续通知`。只使用实际需要的模块。
- 发布给班长时可在末尾写转发请求；直接面向学生时不写内部传达套话。

## 报名字段和建群判断

普通活动报名的基础字段为：`姓名、班级、学号、手机号`。其他字段只在资格核验、材料准备、分组、行程、安全或物资确有需要时增加，并说明用途。不得把年度全院台账的字段整包复制进活动报名表。

手机号属于个人信息，应通过受控表单收集，禁止要求在群内接龙公开填写。表单结果只向本次任务获授权人员开放。

出现任一情况时建议建群：报名后还要补交材料、发布集合/场地变化、培训、排班、行程、成果收集或多轮通知。一次性报名、无需互动且正式渠道能够完成全部后续时通常不建群。输出必须写明 `建议建群/不建议建群 + 理由 + 群用途`，不能只给结论。

## 证明与激励表述

- 外部主办方证书、志愿时长、补贴、保险与学院活动证明分开写，并逐项保留原条件。
- 只有本次已批准提供学院活动证明时才写入通知；表述为“以经核验的实际签到/签退或本次批准的等效参与记录为准”。
- 报名、入群、提交意向或领取物资均不等于实际参加，不得据此承诺活动证明。
- 具体综测分值不写进活动证明正文；通知中的加分表述也必须有当前方案或负责人确认。

## 附件、文章或链接缺失

- 未实际看到的内容不摘要、不补写金额、邮箱、附件名、命名规则或操作步骤。
- 只有确认相应材料会随消息发送时，才写“详见下方公众号文章/附件”。
- 需要但缺失时，在内部草稿中写 `[待附：原通知/公众号文章/附件/报名入口]`，状态标为 `待核验，不可直接发送`。
- 最低可发送事实为：项目、对象、学生行动、报名入口和截止时间均清楚；其中任一项缺失时先索取材料或负责人确认。
- 信息不足时不得主动把内部草稿改称“预通知”并建议发布。只有负责人明确要求另发占位提醒并确认其目的、受众和措辞时，才单独起草不含报名承诺的情况提醒。

## 成稿骨架

```text
【通知】
[正式活动名称]现面向[对象]开展/开放报名。[一句话说明活动与学生要做的事。]

[按需要选择：时间、地点、内容、条件、保障或激励]

❗️报名方式：[表单/材料/步骤/正式渠道]
⏰学院内部截止时间：[月日（星期）具体时刻]
[如有] 官方截止时间：[月日（星期）具体时刻]
[如有] 💬后续通知：[建群方式和群用途]
[如已确认随文发送] 详情请见下方[公众号文章/附件]。
[如需] 辛苦各班长转发至班群。
```

不要为凑齐骨架编写不存在的模块。时间必须带月日、星期和具体时刻；若源文件没有星期，先计算并复核后再补。

## 输出与审核

每次交付分成六项：

1. `可发送通知正文`；若事实不完整则改为 `内部草稿（不可直接发送）`。
2. `报名字段`：基础四项与逐条说明的附加字段。
3. `建群判断`：结论、理由、用途。
4. `随附材料`：实际需要附带的文章、附件、链接、二维码或表单。
5. `核验结果`：缺失、冲突、无法溯源的新增事实、隐私风险。
6. `审批状态`：当前版本、下一审核人、发布人和发布渠道。

审批状态只能写一个明确的下一节点。干事承办时通常依次为 `办公室部长/副部长 → 团委副书记（学生） → 团委书记（老师）`；部长/副部长自行承办时从团委副书记开始上报。不要用“部长或副书记”模糊跳级；承办层级不明时写 `[下一审核人待确认]`。学生版对外通知通常经团委书记终审后，由本次指定发布人发至目标群；负责人明确批准例外时记录该指令。

自检时逐项核对活动名、对象、日期、星期、具体时刻、地点、条件、权益限定、材料、命名、渠道、两个截止时间、附件是否真的随附；再查错别字、重复词、全半角、序号和 emoji。通知完成后沿原任务链逐级上报，不得把草稿直接发群。
