# 活动证明与突出贡献证明

## 不可混淆的两条链

证明链只确认身份，常规批次使用快速路径：

`批准名单 → 一次自动预检并生成 → 一次人工终检 → 部长/副部长批次确认 → 学期集中书记终审盖章 → 扫描发布 → 归档/补开`

加分链只在受限的内部认定表办理：

`当年活动奖励方案 → 出勤统计 → 资格/分值核算 → 人工复核 → 内部认定表`

证明正文不得写具体加分数、缺勤次数、评定公式或“奖励方案1/2/3/4”。普通活动常见的“20分”只是用户说明的经验口径，不能写入证明，也不能在缺少当年规则时自动判定。

两条链必须形成两个独立文件：

- `加分认定表`：受限保存出勤、请假、缺勤、公式、分值和复核记录；
- `证明批准名单`：仅包含内部人员键、姓名、证明类型、活动、角色和批准状态。

证明生成工具只接受第二份文件。发现输入含分值、加分、请假、缺勤、奖励方案、评分或公式字段时应拒绝处理，不得只“忽略该列”。

可直接使用：

- `assets/reward-eligibility-review-template.xlsx`：受限的内部加分/资格复核表，不可直接制证；
- `assets/certificate-approved-list-template.xlsx`：复核批准后单独导出的最小化制证名单。

## 用户指定参考文件形成的当前默认文案

### 普通活动证明

- 标题：`北京工商大学数学与统计学院活动证明`
- 正文：`兹证明以下同学为数统学院{学年}“{活动正式全称}”{角色}：`
- 名单：只列姓名。
- 结语：`感谢以上同学对学院活动的支持与付出，特此证明。`
- 落款：`共青团北京工商大学数学与统计学院委员会`
- 日期：使用实际出具日期，不从旧模板继承。

“活动正式全称”若本身已经包含“活动”“主题活动”等后缀，不得机械重复；“角色”应使用经确认的参与人员、观众、工作人员、演职人员、运动员、后勤保障人员等正式称谓。

### 突出贡献证明

- 主标题：`荣誉证书`
- 英文副标题：`Certificate of Honor`
- 正文：`兹证明以下同学在北京工商大学数学与统计学院{学年}{活动正式全称}中表现突出，特此授予突出贡献证明：`
- 正文后固定留一个完整空白行，再开始名单；正文因活动名较长而增加行数时，名单必须同步下移，不得紧贴或重叠。
- 名单：只列姓名。
- 结语：`特颁此证，以兹鼓励！`
- 落款和日期同上。

若正式活动全称不含“活动”，可在不改变正式名称的前提下调整为“{活动正式全称}活动中”；必须避免“活动活动中”。突出贡献名单必须来自当年奖励方案的核验结果或负责人明确批准，不能由普通参与名单推断。

## 快速开具所需输入

生成待审核稿前只确认以下阻断项：

- 证明类型；
- 学年，格式如 `2025至2026学年`；
- 活动正式全称；
- 角色（普通活动证明必填）；
- 证明批准名单；
- 实际出具日期；
- 突出贡献的批准依据；
- 补开/修订时的原证明标识与原因。

资料齐全时用一条制证批次记录代替完整任务卡，只记活动/学年、证明类型、人数、承办人、审核人和状态。只收到报名表时标为“资格待核验”并停止制证；证据冲突时只列异常，不自行裁决。

## 现有教程和成品形成的当前默认版式

以下是 2026-08-14 依据现有教程、模板和用户当前指示确认的生成默认值；收到新版正式模板时随模板更新。

1. 内部可用学号做去重键，但对外证明只输出姓名。
2. 生成器一次检查输入人数、重复、空值、角色和批准状态；不得静默删除有争议记录。
3. 结构化批准名单中的证明类型、活动和角色必须逐行与本次生成参数一致；任一行错配即整批停止，并只报告异常行号。
4. 显示顺序默认按姓名规范化后的字数稳定排列：三字姓名 → 两字姓名 → 四字及以上姓名；同组保持输入顺序。
5. 名单默认宋体 10.5 磅、无框线表格、单元格居中。表格必须使用固定布局并执行“均分列宽”：表格总宽度等于单列宽乘列数，每个网格列和每个单元格宽度完全一致，单元格左右边距一致，空白补位格也不得合并或改变宽度。
6. 无四字及以上姓名时默认 10 列；存在四字及以上姓名时默认 8 列。突出贡献正文与名单之间固定留一个完整空白行。
7. 所有年份、活动名、角色和日期均为变量，禁止保留模板旧值。

普通活动证明使用 `assets/activity-certificate-template.docx`；突出贡献证明使用 `assets/outstanding-contribution-template.docx`。脚本和模板未变且已有通过的测试时，直接运行 `scripts/generate_certificate.py` 一次；只在代码/模板修改、环境变化或生成报错时再看 `--help` 和用合成名单试跑。生成命令默认同时输出同名 DOCX 和 PDF；`--no-pdf` 仅用于诊断。工具只生成“待审核/待盖章”文件，不生成或粘贴印章。

## 一次终检与学期集中盖章

1. 生成器负责结构性检查：空项、重复、未批准行、上下文错配、输入/输出人数和均分列宽。
2. 人工只终检一次：正式学年/活动名/角色/日期及突出贡献批准依据；名单与人数；PDF 字体、截断、溢出和突出贡献正文后的空白行；DOCX/PDF 一致性。
3. 部长/副部长按批次确认，后续层级不重复同一套格式检查；若当前正式制度另有审批节点，仍按新制度执行。
4. 每学期制作完成后统一交团委书记终审和盖章。盖章后扫描，只确认印章清晰完整、方向正确和页数齐全，再由获授权人员发至相应年级群。
5. 不得把未盖章件标为“已盖章”，不得模拟、复制或合成公章。

## 漏开、错开与补开

收到同学反馈后，先记录请求日期、原证明、问题类型和证据。经核实后进入补开批次：

`反馈待核实 → 核实通过/不通过 → 补开草稿 → 一次终检 → 集中补盖章 → 扫描发布 → 关联归档`

补开件使用新版本，不覆盖原终稿；原件标记“已替代”或“仍有效”。补开日志只对授权人员开放，对外只发布最终证明。

## 必要检查清单

生成器自动检查，人工不重复：禁用字段和分值表述、空项/重复/未批准行、活动/角色错配、人数、占位符、固定布局与均分列宽。

人工只检查：

- 批准名单和突出贡献依据是本学年、本活动的有效版本；
- 学年、活动正式全称、角色和实际出具日期正确，名单与人数一致；
- PDF 每页无方框字、截断、溢出或孤立空白页，突出贡献正文与名单之间有一个完整空白行；
- DOCX/PDF 页数、正文、名单、落款和日期一致，发布版不含学号、班级、电话、身份证号或内部评定字段。
