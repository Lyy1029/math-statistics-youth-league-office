# 团委办公室工作

## 先守住边界

在搜索、读取、解压、OCR、索引、复制或委派任何文件任务前执行以下规则：

- 永不枚举、搜索、打开、复制、哈希、摘要或处理 `通讯信息/**`。疑似通讯录或联系人汇总的副本也停止读取，请用户提供位于允许位置的最小化脱敏摘录。
- 不读取、播放、转码、抽帧、转写、编辑、摘要或生成视频，也不打开明显用于装载视频的压缩包。
- 不读取或处理路径含 `上井冈山表情包`、`表情包`、`托特包设计` 或 `托特包` 的素材。
- 不把排除材料交给子代理、外部服务或其他工具，也不使用此前偶然获知的排除内容。
- 仅处理完成当前任务所需的最小范围。递归检查工作区前读取 [隐私、文件选择与归档](references/privacy-and-archive.md)。
- 如果任务只能依赖排除材料完成，停止相关读取，向用户索要非排除位置的最小化参考。

## 判断任务与权限

先确定用户要咨询、规划、核查、生成、修订、报送准备还是归档，并确认任务是否授权写文件。咨询、核查和诊断不自动写入、发布、发送、盖章、移动或删除；生成或修改任务可创建待审核成果，但仍保留人工审批。

将任务分流：

- 学校/书记通知改写、微信群或年级群文案、报名字段、附件与建群判断：学生通知；
- 活动证明、突出贡献证明、干事或部长及以上任职证明、签到、请假、加分资格：证明与综测；
- 日常讲座、培训、志愿或招募：一般活动；
- 迎新、表彰、晚会等长周期跨岗位事项：大型活动；
- 议程、座次、座签、PPT、分工和纪要：会务；
- 评优、推荐、奖项和表彰：评奖评优；
- 招新、面试、留任、调剂、培训和换届：队伍建设；
- 报名、物料、实施和成果收集：社会实践；
- 通知、表单、催办、收口、核验和提交：材料报送；
- 普通教室代借：一般活动中的教室流程；报告厅不进入该流程；
- 每年一次的全院学生信息收集、核验、变更与权限：学生信息台账；
- 版本、权限、状态、移交和重复文件：档案治理。

跨工作流任务先列依赖，再按：

`规则确认 → 输入核验 → 任务分派 → 材料生成 → 逐级审核 → 执行/发布 → 归档复盘`

优先使用本次正式通知、当前学年方案和负责人本次指示。历史文件仅用于版式和流程参考，不沿用其中的姓名、联系方式、日期、学年、活动名、分值或资格规则。

## 执行真实审批链

默认任务链为：

`团委书记（老师）发起/起草 → 团委副书记（学生）安排 → 办公室部长/副部长研判 → 自行承办或派给干事 → 执行人提交 → 逐级向上审核`

- 紧急程度可影响承办层级、反馈频率和内部截止，不能自动取消审核。
- 用户直接委托生成的成果标明当前状态和下一审核人，不冒充已经通过审批。
- 需要报送学校的文件必须由团委书记终审并发送至相关部门。
- 只有取得明确的人工作为证据后，才能标为 `审核通过`、`已盖章`、`已发送` 或 `已归档`。
- 上级意见或历史版本冲突时列出冲突、影响和待裁决项，不自行挑选有利版本。

处理任务分派、审批、报送或状态时读取 [任务分派、审核与报送](references/governance-and-routing.md)。

## 建立任务卡

在正式生成前尽量确认：

- 原始通知、任务来源、目标产物和正式模板；
- 学年、学期、活动正式全称、日期、时间、地点和对象；
- 当前有效规则、适用范围和版本日期；
- 承办人、初审人、上级审核人和最终发送人；
- 截止时间、内部截止、报送渠道、签字/盖章/公示要求；
- 输入证据、所需字段、个人信息等级和允许访问范围；
- 输出格式、当前状态、异常和待确认项。

不要根据当前日期自动替换学年，也不要猜正式名称、日期、分值、资格或审批状态。关键字段缺失时可以生成缺项清单或醒目标注的草稿，但不能伪装成定稿。

## 改写学生通知

学校或团委书记转发的通知改成学生版通知时，必须读取 [学生通知改写与发布准备](references/notice-writing.md)。把改写视为“事实核验 + 受众转换 + 行动设计”，不是单纯润色。

1. 同时检查消息正文、已提供的附件、公众号文章或链接；给活动名称、对象、时间、地点、条件、权益、材料、命名、渠道和截止时间标明来源。
2. 删除上级对学院的传达话语，改写成学生能直接执行的步骤；保留“拟、原则上、最高、有效、经审核”等限制词。
3. 未实际看到的文章或附件不得补写。需要随消息发送但当前缺失时使用醒目占位并把成稿标为 `不可直接发送/待核验`；不得自行改称“预通知”并建议先发，除非负责人明确要求另发占位提醒。
4. 普通活动报名默认建议收集 `姓名、班级、学号、手机号`；其他字段只按活动需要增加。手机号通过受控表单收集，不写进群通知正文或公开表格。
5. 判断报名后是否存在材料补交、集合变更、培训、行程或持续协调；存在则建议建群并说明用途，不存在则不机械建群。
6. 报名名单不是出席名单。学院活动证明依据经核验的实际签到/签退或本次批准的等效参与记录开具，不因报名自动获得。
7. 交付时分开提供可复制的通知正文、报名字段、是否建群、需随附的链接/附件、待确认项、当前状态和下一审核人。

## 处理证明与加分

证明和加分是两条独立链：

- **活动/突出贡献证明**只确认参与或贡献身份；**任职证明**只确认批准的组织、部门、职务与任期。正文永远不写具体分数、缺勤次数、公式或奖励方案编号。
- **加分**只保留在受限的内部认定表；普通活动“通常20分”是用户说明的常见口径，不是统一制度，每次须确认。
- **突出贡献**只依据本学年、本活动的正式奖励方案或负责人批准名单，不能因活动“大型、耗时”而自动认定。
- 缺少本年方案时只能参考历史格式、列待确认项，不得从往年阈值推断本年资格。

生成或核查证明前必须读取 [活动、突出贡献与任职证明](references/certificate-workflow.md)。只有用户明确要求解释本次提供的奖励方案或确认其适用于当前任务时，才读取 [奖励方案：使用规则与实例](references/reward-scheme-example.md)；其他加分任务只读取用户提供的当前方案，避免用历史数字作锚点。

### 快速开具证明

常规制证默认走快速路径：

`批准名单就绪 → 一次自动预检并生成交付格式 → 一次人工终检 → 部长/副部长批次确认 → 学期集中交书记终审盖章 → 扫描发布`

1. 生成待审核稿前只确认阻断项。活动类为证明类型、学年、活动正式全称、实际出具日期和证明批准名单；普通证明加角色，突出贡献加批准依据。任职类为学年、实际出具日期和任职批准名单；干事逐行确认班级、学号、组织、部门和职务，部长及以上逐行确认组织、职务及任期起止。资料齐全时不另建完整任务卡。
2. 只有报名表时标为“资格待核验”，不制证。加分认定表与证明批准名单必须分离；生成器只接受后者。
3. 活动/突出贡献证明直接运行 `scripts/generate_certificate.py`；干事及部长以上任职证明直接运行 `scripts/generate_appointment_certificate.py`。任职生成器允许在一张名单中混合两类记录：按组织和部门汇总干事批量证明，为每位部长、主席、团委副书记等生成个人聘请证书。干事保留 DOCX 并导出 PDF；部长及以上不经 Word，以 `assets/leader-appointment-background.png` 保留正式 PDF 原稿的边框、水印、标题、横线和落款，覆盖姓名、职务、聘期和日期后直接输出 PDF。部长及以上动态文字必须使用 `assets/fonts/SourceHanSerifSC-SemiBold.otf`，并按原 PDF 的逐字坐标和字距绝对定位；活动、突出贡献和干事证明使用 `assets/fonts/NotoSerifSC-Regular.otf`。可转换内容按批次启动 LibreOffice，导出后按类型检查对应字体嵌入；字体缺失、大小异常或检测到替代字体时停止。脚本和资产未改动且上次测试通过时，不必每批重读 `--help` 或用合成名单试跑；仅在脚本/模板/字体修改、环境变更或生成报错时重测。部长及以上类型不支持 `--no-pdf`。
4. 空项、重复、未批准行、上下文错配、人数和均分列宽由生成器一次检查，通过后不再人工重复逐项勾验。有争议、字段缺失或上下文冲突时停止并只报异常行号。
5. 普通活动证明正文只证明活动与角色；突出贡献证明正文只证明表现突出并授予突出贡献证明。两者均只公开姓名。干事任职证明按用户确认的行政模板列姓名、班级、职务和学号，只作受控交付，不在公开群或公开仓库散发；部长及以上个人聘请证书仅列姓名、组织、部门、职务和聘期。突出贡献证明的正文结束后必须保留一个完整空白行，下一行再开始名单；正文换行时名单应同步下移。
6. 活动类名单使用固定布局、无框线、均分列宽的表格；干事任职名单使用固定四列表格并保留表头。人工终检只做一次：核对正式字段及批准依据、名单与人数、任职类型与任期、PDF 动态文字已嵌入对应内置字体且无替代字体/方框字/截断/溢出；对有 DOCX 的类型再核对 DOCX/PDF 一致性，部长及以上只核对直接生成的 PDF 与正式原稿版式。
7. 只交付 Word、PDF、人数、异常（如有）、当前状态和下一审核人。同一批次不在每个层级重复同一套格式检查；工具不得生成、复制或合成公章。盖章后扫描只核对页数、方向、清晰度和印章完整性，再由获授权人员发至年级群。
8. 漏开或错开经核实后进入补开批次；新建版本并关联原因和原件，不覆盖已发布终稿。

## 执行办公室工作流

### 一般活动、大型活动与会务

读取 [通知、一般活动、大型活动与会务](references/activity-operations.md)。输出任务卡、倒排期、分工、通知、报名字段、场地、物资、签到签退、议程、PPT/PDF、座位/座签、风险、现场清单和复盘中实际需要的部分。

- 报名名单不等于实际参加；请假、缺勤、补签和提前签退只按当前制度处理。
- 教室借用前核对学校最新版流程；不得从 `通讯信息/**` 或旧文件硬编码的个人电话获取联系人。
- 大型活动的获奖主表、表彰决定、上台代表、座位、座签和议程应基于同一冻结版名单。
- 旧安全预案只作反例。不得指示未经训练的学生冒险灭火或控制当事人。
- 核查 PPT、座位图、座签或工作分工表时读取 [办公会务视觉预检](references/visual-preflight.md)。视频始终不在本技能范围内。

### 评奖评优、招新留任与社会实践

读取 [评奖评优、招新留任与社会实践](references/awards-recruitment-practice.md)。把最新正式文件转成条件、名额、材料、截止和核验清单；建立收件、退补、复核、报送和结果状态。

- 不自行设定或放宽资格、名额、评分、回避、录取、调剂、公示或处分规则。
- 只有已由有权人员作出拟推荐决定但结果尚未终审时才使用 `拟推荐`；仅有报名或材料收件时使用 `资料待核验`、`资格待核验` 或 `待审核`。
- 缺少招新/留任统一量表和决定规则时，只整理材料与缺口，不从历史表单反推制度。
- 社会实践跟踪申请、实发、签收、实施、成果和审核；不解释无标题或口径不明的字段。

### 学年日历与内部管理

读取 [学年常见活动与内部管理](references/annual-calendar.md)。历史日期只是启动参考；每学年按学校日历和正式通知重排，逐项年度化标题、周年、学年、主办方、负责人和截止日。

年度全院学生信息收集、人数核对、学籍变更或台账权限任务必须读取 [年度全院学生信息台账](references/student-information-ledger.md)。

## 保护个人信息

- 只收集、读取和输出完成任务所需的最少字段；制度、脚本和示例优先用岗位称谓及合成数据。
- 对外活动证明通常只含姓名。学号可在受控内部表中去重，但电话、身份证号、家长联系方式、照片、签名、请假事由、成绩和排名不得进入普通日志或对外材料。
- 默认只报告记录数、字段、缺失数、重复数、异常行号和状态，不在聊天中复述真实个人值。
- 未经批准不跨表关联身份，不上传、群发或向外部系统传输个人信息。
- 全院学生信息每年集中收集一次；完整台账通常只允许老师和涉及该项工作的部门部长查看。班长、干事或协作人员不因转发、催办或制作表单自动获得总表权限。
- 分享前检查批注、修订、隐藏文本、隐藏表、文档属性和旧模板残留。

涉及真实名单、敏感材料、重复副本、版本、归档或交接时读取 [隐私、文件选择与归档](references/privacy-and-archive.md)。

## 管理版本与归档

- 保留原始输入，不覆盖用户原件。区分 `资料待核验`、`草稿`、`待审核`、`待签字/盖章`、`已批准/已盖章`、`已发布`、`已归档` 和 `已替代`。
- 不因文件名含“终稿”或“已盖章”就相信状态；核对审批记录或真实扫描件。
- 同一正式材料维护一个权威版本，记录派生 DOCX/PDF/扫描件、版本、哈希、批准人、时间和替代关系。
- 不因发现重复而删除。先列清单，删除、覆盖、移动或清理须另获授权。
- ZIP 仅作交付包，不作权威档案；排除 `.DS_Store`、`__MACOSX`、`._*`、`~$*` 和重复外层文件。

## 交付

先说明已经完成的成果，再列待确认项和下一审核节点。每个输出标明用途、适用学年/活动、版本和状态，并给出可点击路径。对推断明确标注依据；未审核文件必须写明“草稿”或“待审核”。结束前复核范围、事实、名单、格式、隐私、审批和归档。
